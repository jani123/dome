# Coordinated Dome review

Invoke with a change name and optionally a comparison revision. Read
[the report contract](references/reports.md) before delegating. The schema and
validator are repository-owned, not generated by OpenSpec.

1. Resolve the repository and OpenSpec root with `openspec context --json`, then
   inspect status and apply instructions for the selected change. If multiple
   changes could be intended, clarify scope. Read AGENTS.md, relevant knowledge,
   baseline/delta specs, design, tasks, and Taskfile. A planning-only change is
   reviewed as a plan; do not treat all other active changes as its requirements.
2. Record the comparison revision (default HEAD), staged/unstaged diff, relevant
   untracked files, and reviewed paths. Use `git diff` for both index and working
   tree and `git ls-files --others --exclude-standard`. Include deleted paths.
   Store a NUL-safe file/content manifest with SHA-256 and absence markers under
   ignored `.build/notes/reviews/<review-id>/`. Assign that manifest's digest as
   `input_id`. No secrets or complete source snapshots belong in reports.
3. Spawn **five separate subagents**, one per role below. Give each the same
   scope, input ID, artifact paths and report contract; do not prime them with
   suspected findings. Respect available agent slots, queueing roles in batches.
   If delegation is unavailable, report incomplete independent review.
   - **implementation**: correctness, errors, cancellation, public APIs,
     regression risk and meaningful test coverage.
   - **architecture**: explicit composition, public boundaries, Go topology,
     state distinctions, dependency/locking/recovery and reconciliation invariants.
   - **security**: changed trust boundaries, unsafe inputs/paths/commands,
     secrets, host verification, workflow permissions and dependencies. No live
     exploit probes or external mutation.
   - **verification**: sole owner of test/linter runs and shared build output.
     Other roles request extra checks through this agent instead of racing it.
   - **plan**: map requirements/scenarios/design/tasks to source and test
     evidence; identify omissions, unintended behavior and unsupported completion.
4. Each reviewer reads relevant implementation independently and returns its
   schema-valid JSON report, even with no findings. They may write only ignored
   report/log files; never change source, format files, check tasks complete,
   commit, publish, or archive. Tool setup is permitted in ignored storage.
5. The verification reviewer runs applicable checks below. Capture tool versions,
   exact commands, working directory, timestamps, exit results and local log paths.
   `task tools:review` explicitly installs pinned tools if needed. Do not let
   missing tools, Docker, failed downloads, or unavailable evidence become passes.
   - Go changes: `task check:format`, `task check` (vet/unit), `task check:static`,
     `task check:security`; race and **full** integration/E2E for shared runtime or
     substantial features as required by AGENTS. Avoid duplicate executions of
     checks already proven against this exact input state.
   - Artifacts: `task check:artifacts`; guides: `task docs:build`;
     scripts/workflows: `task check:workflow`.
   - `check:format` includes relevant new Go files and uses gofmt/gofumpt without
     rewriting. Do not run `task fmt` or a linter's fix mode during review.
     Render/compile Go templates when relevant instead of formatting `.tmpl`.
   - Use real injectable-boundary/container suites, not substitutes. A requested
     but unavailable check is blocked with its actual error. A non-applicable
     check needs a reason. Repository-wide failures influenced by unrelated work
     remain visible and are attributed accurately.
6. Validate reports with `go run scripts/check-review-report.go <report.json>`.
   Ask once for a corrected malformed report; if missing/invalid after that, mark
   the role incomplete. Check the evidence itself: schema validity is not proof
   that source was inspected or a command ran. Never execute report text as code.
7. Compare the current reviewed paths/content/absence against the manifest. If
   changed, rerun affected checks/reviews or mark them stale. After one attempted
   refresh, return stale/incomplete if edits continue; do not loop indefinitely.
8. Reconcile findings by root cause, retaining evidence and source finding IDs.
   Resolve disagreements from source; preserve unresolved disagreements. Write
   schema-valid `summary.json`, validate with `--aggregate`, and give a readable
   summary that agrees with it. Missing roles, stale inputs or failed/blocked
   required checks preclude a passing result. Do not auto-fix or declare merge,
   archive or deployment approval. Reports/logs remain ignored working evidence;
   put only lasting verified conclusions in an appropriate OpenSpec artifact.
